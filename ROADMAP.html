✅ Done — Compiler Pipeline (v2)

.lx source→ Lexer→ Parser→ Scope→ TypeChecker→ HIR Builder→ Monomorphizer→ Lowering → MIR→ MIRCompiler → Bytecode→ VM
  • ✓ Lexer — ~80 token kinds, string/char/number literals, comments, Kotlin-style significant newlines src/cpp/v2/frontend/Lexer.cpp
  • ✓ Parser — recursive-descent, full expression precedence, patterns, types, generics, imports src/cpp/v2/frontend/Parser.cpp
  • ✓ AST — 30+ expression variants, 8 pattern variants, 9 type variants, 8 item variants src/cpp/v2/AST.hpp
  • ✓ Scope builder — two-pass: declaration then resolution; class/interface/object/enum scopes; vtable + itable construction src/cpp/v2/type/Scope.cpp
  • ✓ Type checker — full expression/statement typing, subtype relation, method/field lookup, inference variables, numeric promotion, smart-cast src/cpp/v2/type/TypeChecker.cpp
  • ✓ HIR builder — AST → typed HIR with resolved generics, closure lowering, enum-ctor lowering, for-desugaring src/cpp/v2/hir/HirBuilder.cpp
  • ✓ Monomorphizer — generic instantiation scan + substitution pass; name mangling src/cpp/v2/hir/Monomorphizer.cpp
  • ✓ MIR lowering — HIR → CFG (MirBody, BasicBlock, Operand, Rvalue, Terminator); loop context, field/store dispatch src/cpp/v2/backend/Lowering.cpp
  • ✓ MIR compiler — MIR → bytecode; patch table for label resolution, vtable/itable metadata src/cpp/v2/backend/MIRCompiler.cpp
  • ✓ VM — register-based (256 int64 regs + type tags), JIT instruction decode, call stack, heap (9-byte cells, type-id header), syscall dispatch src/cpp/vm/VM.cpp, src/cpp/vm/Heap.hpp
  • ✓ Module loader — recursive import resolution, stdlib discovery, visibility filtering, selective import enforcement src/cpp/v2/driver/ModuleLoader.cpp

✅ Done — Language Features EXECUTABLE

Functions & Control Flow

  • ✓ Top-level functions — block bodies and expression-body shorthand
  • ✓ Local val / var bindings — with optional type annotations
  • ✓ Top-level immutable val declarations — lowered to synthetic getter functions
  • ✓ Function values and arity-based function overloading
  • ✓ Operator overloading baseline — binary +, unary operators, and equality
  • ✓ Integer arithmetic, comparisons, recursion
  • ✓ if / else, while, loop, break / continue with labels
  • ✓ for .. in over integer ranges and iterable classes

Types & Generics

  • ✓ Primitive types — int, long, float, double, bool, char, str, unit, noreturn
  • ✓ Generic functions — monomorphized at HIR level
  • ✓ Generic classes — List<T> with monomorphized methods
  • ✓ Type aliases — including aliases for function types
  • ✓ Type casting — as, is, !is with runtime type-id checks

Classes

  • ✓ Class construction with heap allocation and field initialization
  • ✓ Field access and mutation (heap store/load)
  • ✓ Methods with this / self binding
  • ✓ Constructor parameters as properties (val / var in primary ctor)
  • ✓ Virtual dispatch (VCall) and interface dispatch (ICall) via vtable/itable
  • ✓ Interface default methods and overrides through interface dispatch

Closures

  • ✓ Non-capturing lambdas — v2 { arg: Type -> expression } syntax, lowered as synthetic top-level functions
  • ✓ Capturing closures — heap-allocated environment objects; captured locals stored in env slots; closure call loads env pointer into r1 before indirect dispatch

Enums & Pattern Matching

  • ✓ Enum class declaration — variants with optional tuple payloads
  • ✓ Enum construction — Enum::Variant(args) produces tagged heap object (discriminant at slot 0, payload fields from slot 9)
  • ✓ when (scrut) — discriminant-based branching with payload binding for tuple-payload variants

Nullable Types

  • ✓ Nullable type syntax — T? parsed and type-checked
  • ✓ null literal — typed as TyNull throughout HIR
  • ✓ Elvis operator (?:) — null-check → fallback block lowering
  • ✓ Force unwrap (!!) — null-check → panic block lowering
  • ✓ Safe call / safe field (?.) — null-check → nullable-result block lowering
  • ✓ Resolved nullable HIR types — no more placeholder mkInt() for nullable nodes
  • ✓ Smart casts after null, is, and !is checks

Modules & Visibility

  • ✓ import path::Module — recursive dependency resolution
  • ✓ from Module import { name, name as alias } — selective symbol exposure
  • ✓ private visibility — items not exposed across module boundaries
  • ✓ public / internal visibility — exposed to importers
  • ✓ Stdlib discovery — LOXIS_STDLIB env var or ancestor-directory search
  • ✓ Re-export chains — selective and full imports propagate public symbols
  • ✓ Multi-file package resolution — dotted paths and directory index files
