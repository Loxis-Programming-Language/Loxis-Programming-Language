Loxis v1 和 v2 的区别

基于 PR #1 的 diff：v1 是当前可运行的编译器管线；v2 是新增的一套更接近 Rust/C++ 系统语言方向的编译器骨架，包含 AST、parser、MIR、类型系统和标准库草案，但入口目前还没有真正接通完整前端。

一句话结论

v1

当前主线实现

语法较小，直接从现有 AST 生成 IR，再编译成 VM bytecode 运行。PR 里只对 v1 做了 keyword token、CRLF、异常和 VM 分支修复。

v2

新编译器架构

新增独立命名空间 loxis::v2，目标是支持模块、泛型、trait、struct、enum、模式匹配、引用、raw pointer、MIR 和更正式的类型系统。

当前状态

更像原型包

Driver.cpp 里 frontend/typecheck 代码被 #if 0 包住，当前运行时创建的是空 Module，所以 v2 还不是完整可用编译器。

核心差异

维度 v1 v2
定位 现有 Loxis 编译器，重点是把当前语言子集跑通。 下一代编译器，目标是系统语言级别的语义模型。
入口 src/cpp/main.cpp 构建为 Loinx。 src/cpp/main_v2.cpp 构建为 LoinxV2。
语法规模 函数、类、变量、if、while、return、print、表达式、数组/成员访问等。 新增规格覆盖 module/use、fn、let mut、struct、enum、trait、impl、match、closure、try、cast、引用和指针。
Token 原本 keyword 依赖 Ident + lexeme；PR 中改成 KwFun、KwClass 等专用 token。 有独立 v2 token 定义，面向更丰富的 Rust-like 语法。
中间表示 AST 直接生成当前 IR，再交给 backend 编译。 新增 MIR：local、basic block、terminator、statement，用 Lowering 从 AST 降到 MIR。
类型系统 已有较轻量的类型处理，主要服务当前语法。 新增 TypeChecker、Scope、Type，覆盖 primitive、tuple、array、ref、raw pointer、function、struct、enum、trait 方向。
标准库 没有这次新增的独立 std 草案。 新增 std/core.lxs、option.lxs、result.lxs、vec.lxs、string.lxs、io.lxs。
可运行性 主线仍按原管线运行。 代码量完整，但 driver 当前没有启用真实 lexer/parser/typechecker 接线。

v2 新增模块

Frontend

v2/frontend/Lexer.* 和 Parser.* 新增独立前端。Parser 文件约 1100 行，是 PR 里最大的新增点。

AST

v2/AST.hpp 定义了 Path、Type、Pattern、Expression、Statement、Item、Module 等更完整的语言表面结构。

Type

v2/type 提供 Scope、Symbol、Type 和 TypeChecker，开始处理作用域、函数返回、循环、引用、cast 等语义。

MIR

v2/mir/MIR.hpp 定义 basic block、local、operand、statement、terminator，明显比 v1 IR 更适合后续优化。

Backend

Lowering 把 v2 AST 降到 MIR，MIRCompiler 把 MIR 编译到当前 VM 的 Chunk。

Driver

存在 compileAndRun，但当前真实 frontend/typecheck 调用被禁用，实际只创建空模块再跑后续流程。

PR 里对 v1 的改动

词法和解析更明确

v1 的 keyword 现在变成专用 token，不再靠字符串比较判断 fun、class、var、if 等。错误信息也从 token 数字变成可读文本。

兼容和错误处理

lexer 支持 CRLF；main 里 verbose 参数处理更稳；异常打印从吞掉 RuntimeError 变为输出 GalVMError 和普通 exception。

VM 小修

删除了 VM.cpp 里一个重复的 OperandTag::Reg 分支，让 Imm64 分支逻辑更清晰。

构建调整

MSVC 下加入 /utf-8，并新增 LoinxV2 target。原 Loinx target 仍然存在。

当前风险点

不要把 v2 当成完整可运行的新编译器。 PR 标题写的是完整 developer source package，但从 Driver.cpp 看，v2 的 lexer、parser、scope builder、type checker 调用还被 #if 0 禁用。也就是说代码结构已经放进来了，但端到端编译真实 v2 源码这件事还没接上。

建议 Review 重点

1. 先确认 Loinx v1 是否仍能正常构建和跑测试
2. 单独构建 LoinxV2，确认新增代码是否编译通过
3. 检查 Driver.cpp 的 #if 0 是否是临时提交
4. 检查 std/*.lxs 是否只是草案，还是要进入主线
5. 评估 CMake GLOB_RECURSE 是否符合项目风格
